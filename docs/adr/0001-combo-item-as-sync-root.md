# 0001 — 重量同步以组合条目为独立根源，提醒驱动同步

FitPlan 原有的重量模型以 `exercises.defaultWeight`（根源重量）为同步源头：动作编辑页与训练页精确输入对话框都能把一个值覆盖写入该动作在所有组合中的条目，会抹掉各组合的个性化重量。我们决定改为：**组合条目目标重量是各组合独立的根源**，训练页/主页输入的是"当次重量"（按日期+动作记录，不写回组合），当历史当次重量超过基准时在后续训练日以非阻断提示条提醒，用户确认后才写入组合条目（可选全量）。

否掉的方案：①当次重量写回当前组合条目、提醒只针对其他组合——会让"记录实际重量"与"修改计划"两个意图耦合在一次输入里；②保留旧的全量同步入口与提醒机制并存——同一对话框承担两种语义，且全量覆盖正是本次要消灭的行为。`defaultWeight` 保留但降级为"添加到组合时的预填默认值"，UI 术语由"根源重量"改为"默认重量"。

## Consequences

- 训练页重量行"输入即持久化到组合"的旧行为被刻意移除——不要把它当作回归缺陷修复回去。
- 组合目标重量的修改入口只剩两个：组合编辑页行内编辑、提醒条确认同步。
- DB v3→v4 新增当次重量记录表与动作级"已处理重量"列（忽略/同步后同重量不再提醒）。
