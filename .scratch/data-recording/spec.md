# Spec：data-recording——更多记录数据的方式

Status: ready-for-agent

来源：2026-10-01 盘问会话（flomo 借鉴分析 → AI 分析前置 → 记录项盘问）。术语见仓库根 `CONTEXT.md`（逃组 / 当日备注 / 动作备注 / 体重记录 / 移除安排 / 训练用时均已更新）。

## Problem Statement

FitPlan 现在能记录的只有「组数、次数、重量」和一个自由形态的训练记录 Tab。使用者想记的更多：练完想留一句状态说明没有地方；体重无处可记；练到中途放弃时，现行「逃了」把一整天标记为逃课，既不符合实际（放弃的只是当前那组），还会把已完成训练的用时信息一并抹掉；练了多久不留任何痕迹。这些缺口同时也是 AI 分析健身状况（独立后续功能）的素材前置——没有体重、备注和训练节奏数据，分析只能看到重量数字。

## Solution

在不破坏离线原则（无网络、无账号、可选低负担）的前提下新增四类记录能力并修正逃课模型：

1. **体重记录**：天 + 训练者一条，重复覆盖，训练日与休息日都可记，可选记录（不催、不标漏记）；
2. **备注双轨**：当日备注（天 + 训练者）与动作备注（天 + 动作），各一条、重复覆盖，并回显上次动作备注；
3. **组时间戳 + 训练用时历史化**：每组打卡自动记时刻；用时 = 首组到末组打卡的时间差，按训练日留存、周计划页可回看、中途结束也产生；
4. **逃组模型**（取代天级逃课）：每个计划组三态——未练 / 打卡 / 逃。通知「逃了」= 当前组标逃并结束会话；清单内可手动标逃/取消（力竭跳组场景：逃第 3 组，继续练第 4 组）；打卡覆盖逃组；完成判定不变。另新增「移除安排」：清掉某天计划回未安排，历史记录保留。

## User Stories

1. 作为训练者，我想在主页快速记下当天体重，以便积累身体数据供回看与日后 AI 分析。
2. 作为训练者，我想在休息日也能记体重，以便体重数据不因休息断档。
3. 作为训练者，我想重复输入体重时直接覆盖当天旧值，以便当天始终只有一个权威数字。
4. 作为训练者，我希望 app 不催我称重、不显示漏记提示，以便体重记录零负担。
5. 作为训练者，我想在主页给今天写一句当日备注（如「状态差」），以便日后回看时知道训练背景。
6. 作为训练者，我想在休息日也写当日备注（如「出差」），以便解释当天为什么没练。
7. 作为训练者，我想在动作卡里写动作备注（如「肩膀不舒服」），以便精确记录该动作当天的情况。
8. 作为训练者，我想在下次训练同一动作时看到上次的动作备注，以便避免重复不适。
9. 作为训练者，我希望每组打卡自动记录时刻且无需手动操作，以便沉淀训练节奏数据。
10. 作为训练者，我想在周计划页看到每天的训练用时，以便一眼回看各天投入。
11. 作为训练者，我想让中途放弃的训练也留有用时，以便真实投入不被抹掉。
12. 作为训练者，我在通知上按「逃了」时只逃掉当前这一组，以便精确记录放弃的位置。
13. 作为训练者，我想在清单里手动标逃某一组并继续练后面的组，以便力竭跳组而不放弃整个动作。
14. 作为训练者，我想让逃掉的组可以直接打卡覆盖，以便补做后记录自动修正。
15. 作为训练者，我想取消某一组的逃标恢复未练，以便纠错。
16. 作为训练者，我想清掉某天不想练的安排，以便当天回到未安排而不是被迫标逃课。
17. 作为训练者，我希望移除安排后该天已有的打卡、逃组、备注全部保留，以便调排程不毁历史。
18. 作为第二个训练者，我希望体重、备注、逃组、用时都按训练者隔离，以便多人互不干扰。
19. 作为训练者，我希望导出的 Markdown 包含体重、备注、用时与逃组标注，以便离线备份完整。
20. 作为升级用户，我希望旧数据无损迁移（历史打卡不参与用时、旧天级逃课转为组级逃标），以便升级零损失。

## Implementation Decisions

- **数据库 v7→v8，非破坏迁移**（沿用既有迁移惯例）：
  - 新表 `body_weights`：date + userId 唯一，weight 实数（kg，库内原值口径，lb 不换算——沿用 PR 页口径），重复输入 REPLACE 覆盖；
  - 新表 `day_notes`：date + userId 唯一，note 文本，重复覆盖；
  - 新表 `exercise_notes`：date + exerciseId + userId 唯一，note 文本，重复覆盖，外键级联删除动作；
  - `set_checkins` 新增 `checkedAt` 打卡时刻列：打卡/覆盖时写入；历史行 NULL，不参与用时推导；
  - 新表 `set_skips`（逃组）：date + comboItemId + setIndex + userId 唯一，标记行存在即逃；不改动 `set_checkins`「行存在即打卡」的既有语义；
  - `day_plans.skipped` 列保留但弃用（避免重建表），代码读写路径全部切到 `set_skips`；迁移时历史 skipped 天 → 该天所有未打卡组写入 `set_skips`。
- **用时推导**：不落新表，顶层纯函数按（天 + 训练者）从打卡时刻推导——无打卡不产生；单组约 0 分钟；首末时刻差即用时；完成通知行为不变。
- **逃组接线**：通知「逃了」= 当前组标逃 + 结束会话；直接打卡推进规则改为「第一个既未打卡也未逃的组」（`QuickCheckIn` 同步调整）；清单组行新增标逃/取消入口；动作完成判定维持「全部组打卡」。
- **主页**：整日「逃课卡片」与反悔流移除，今日清单常驻（含未安排日）；当日备注入口在清单顶部、休息日卡片同享；体重入口在训练日清单上方与休息日卡片。
- **移除安排**：周计划页单日操作，删除该天计划行（数据层补 delete 能力）；该天打卡/逃组/备注全部保留。
- **回显**：动作卡展开区显示该动作最近一次（当天之前）的动作备注。
- **导出**（Markdown 扩展）：打卡段落动作行并入动作备注、当天段落并入当日备注与用时；新增「## 体重记录」段（按导出范围过滤）；周计划类型列回归「休息日/训练日」两分支，逃组在打卡段落按组标注。
- **多训练者**：三张新表与逃组表全部携带 userId；用时、导出、清单状态均按 activeUserId 过滤（沿用第九轮范式）。

## Testing Decisions

- **只测外部行为，不测实现细节**；沿用现有三层 seam，零新增测试基础设施：
  - **ViewModel + Fake DAO**（现有 FakeDaos 范式，60 个测试先例）：逃组标记/取消/打卡覆盖、直接打卡跳过逃组、三类新记录的覆盖语义与多训练者隔离、移除安排不损记录；
  - **顶层纯函数**（`buildPrEntries` 同风格）：用时推导边界（无打卡、单组、跨小时、中途结束、历史行无时刻）；与 `PrRecordsTest` 同款写法；
  - **导出纯函数**（`MarkdownExporterTest` 先例 9 个）：新导出口径逐项。
- Room 迁移正确性不写 JVM 测试，沿用「全量构建 + 真机覆盖安装验收」惯例（v6→v7 先例）。

## Out of Scope

- **AI 分析**：独立 feature 立项（BYOK 接入 API），届时才修订需求「不做 AI」红线；本 spec 是其数据前置；
- **手环/睡眠数据**：已 park 在 wearable-health-data issue（Health Connect 与 CSV 导入两路线，立项前需真机验证同步支持）；
- RPE、一天多条体重、称重提醒/漏记标记、组间已休读数、提醒条时刻上下文、出勤提示——盘问中明确否决；
- 需求红线零触碰：云同步、账号、Health Connect、Wear OS、训练提醒、组间休息计时器、社交、成就、排行榜、图表统计。

## Further Notes

- 逃组模型是对第七轮「训练会话 + 逃课」的语义修正，动机链：天级逃课抹掉部分完成训练的用时 → 动作级 → 组级（用户明确：计量单位小到每组，力竭跳组是真实场景）。
- 「移除安排」源于用户陈述「某天不去练就不会去安排」，现状 DayPlanDao 无删除能力，属顺手补齐的缺口。
- 实现顺序建议：schema 迁移 → 逃组/时间戳（打卡主链路）→ 用时推导 → 体重/备注 → 导出与展示位。
